Project 01 / 10

01 / ELVERAN — watch catalogue

Explore the live demo ↗

Work completed. Built a catalogue, product pages, search, filters, sorting, favourites, a cart, and a comparison view for up to four watches. The comparison uses product attributes and practical style notes so a buyer can decide which model fits a situation. A separate customer account area stores profile details and order history. The local server includes an admin panel for product edits, photos, incoming orders and order status.

Stack and tools. React, Vite and a Node.js server. Product and order data persist on the server in the local build. This is custom code.

Visual decisions. Cream and white surfaces, dark text and restrained gold accents keep the watches readable. Large product images carry the page; controls are grouped around the catalogue instead of being scattered through it.

Competitive thinking. A watch buyer needs more than a photograph and price. Search, structured filters and side-by-side comparison answer questions that otherwise become messages to the seller. This is the reason for the interface; it is not a claim that the site has beaten another retailer in sales.

Automation and data. In the local server build, a submitted order reaches the admin panel and the server calculates its total from current product data. Admin edits update the storefront. Favourites, comparison choices and the cart are saved in the visitor's browser. Online payment is not implemented. Public deployment still requires hosting, HTTPS, business details and current stock data.

Build time. Actual working hours were not logged.

02 / ELVERAN — accessories homepage

Explore the live demo ↗

Work completed. Created a separate editorial route into the ELVERAN assortment, with a brand-led opening screen, navigation to men's and women's selections, category sections and a route toward product discovery.

Stack and tools. This is part of the local ELVERAN codebase, built with React and Vite. It uses the same project environment as the watch catalogue.

Visual decisions. A quiet palette, generous space, large photography and serif typography shift the first impression from catalogue to brand. The first screen gives the visitor a choice of direction before displaying a dense product grid.

Competitive thinking. The page is designed for a visitor who does not yet know which item to buy. Clear category routes reduce the work of finding a starting point; the editorial image helps the store feel like one brand rather than an uncurated list.

Automation and data. This page is a navigation and presentation layer. It does not add a separate automation of its own. Store and admin functionality belong to the ELVERAN project described above.

Build time. Actual working hours for this page were not logged.

03 / ORVEX — digital studio

Explore the live demo ↗

Work completed. Built a studio website with service, process, project and contact routes. The contact interface validates the information a prospective client enters. The code also contains an optional path for managing published project and review content through Supabase.

Stack and tools. React and Vite, with custom page components and contact-form code. Supabase support is conditional on configuration.

Visual decisions. Near-black and graphite surfaces with a red accent create a more direct visual identity than a neutral agency template. The page uses clear section breaks to keep the offer, process and proof easy to locate.

Competitive thinking. A potential client needs to understand what the studio does and how a project begins. The structure brings those answers closer to the first contact action. This is a positioning choice, not a measured lead-generation result.

Automation and data. Form validation and a submission path are implemented in code. Project and review data can be read from Supabase when configured, with local fallback content. I have not verified a live production contact-delivery workflow, so I do not claim that enquiries are currently being routed to a CRM or email inbox.

Build time. Actual working hours were not logged.

Project 04 / 10

04 / NORTHLINE — architecture studio concept

Explore the live demo ↗

Work completed. Built a responsive architecture page with a scroll-controlled opening scene. Three room images move and blend as the visitor scrolls: living room, dining room and bedroom. Added navigation, work and process sections, and a demonstration enquiry form. Captured three stills and a short video of the opening interaction. Added a project explorer with three interior photographs and responsive concept details.

Stack and tools. Hand-coded HTML, CSS and JavaScript, including a Canvas animation driven by scroll position. Codex assisted the implementation. MotionSites informed the motion reference. No Tilda template or copied animation component is used.

Visual decisions. Limestone, oak, muted olive and off-white support the architectural imagery. A large serif headline stays on the first screen while the rooms change behind it. The motion has a reduced-motion path.

Competitive thinking. The changing rooms let a visitor experience more than one interior before leaving the hero. The studio's visual approach is demonstrated in the opening interaction rather than explained only in a paragraph. No competitor ranking or conversion result is claimed.

Automation and data. Canvas rendering, captions and progress indicators respond to scroll automatically. The enquiry form confirms input on the page but sends nothing to a server. The public demo uses images and local controls; the enquiry form does not submit to a server.

Build time. Actual working hours were not logged.

Explore the live demo ↗

Work completed. Built a responsive service page with an introduction, treatment information, expandable answers to common questions and a consultation enquiry flow.

Stack and tools. Built with HTML, CSS and JavaScript. The site is not built with Tilda.

06 / ROVE — furniture concept

Explore the live demo ↗

Work completed. Built a product-focused page for a chair, including a visual introduction, material and specification sections, a finish selector and a request form.

Stack and tools. Built with HTML, CSS and JavaScript. No template builder was used.

Visual decisions. Warm grey, stone, charcoal and walnut tones keep attention on the furniture silhouette and material details. A restrained layout leaves enough space to inspect the product.

Competitive thinking. A visitor comparing furniture needs to understand scale, finish and material before asking for a quote. The page places those details around one object instead of hiding them in a large catalogue.

Automation and data. The finish selector changes the chair photograph between warm walnut, natural oak and smoked ash; the selected state and image stay in sync. The request form is a demo; there is no live inventory, order processing or external integration.

Build time. Actual working hours were not logged.

07 / SOLA — small hotel concept

Explore the live demo ↗

Work completed. Built a responsive hospitality page with the location, room types, experiences and a trip-planning form. The visitor can enter arrival, departure and guest count. Added photographic room cards and a room comparison control.

Stack and tools. Built with HTML, CSS and JavaScript.

Visual decisions. Sand, warm white and sage connect the page to the coastal setting. Photography establishes the atmosphere while the trip-planning route remains visible.

Competitive thinking. A guest who likes the place should not have to hunt for the first booking step. The design keeps date selection close to the visual introduction, then provides room context lower on the page.

Automation and data. The form checks that departure is after arrival and shows a demo confirmation. It does not check real room availability, take payment or make a reservation. The date form and room comparison run locally. They do not check real availability or create a booking.

08 / KADR — portrait photography concept

Explore the live demo ↗

Work completed. Built a portfolio page with a portrait-led first screen, image gallery, process explanation and enquiry form. Adjusted the portrait crop and contrast so the subject remains visible, with a gallery lightbox and a session selector.

Stack and tools. Built with HTML, CSS and JavaScript. The displayed photographs come from Pexels and are credited in the project source notes. They are reference images, not photographs by a real KADR studio.

Visual decisions. Near-black, grey and off-white create a gallery setting and keep colour in the portraits. Tight typography and a simple grid give the work room to speak.

Competitive thinking. Photography clients decide first whether they trust the visual style. The gallery is placed ahead of long explanations; the process section then makes the next step clear.

Automation and data. Navigation and the demonstration form work in the page. The form does not deliver enquiries, and no booking calendar is connected. The lightbox and session selector run in the browser; the enquiry form does not send messages.

Build time. Actual working hours were not logged.

Project 09 / 10

09 / EMBER — coffee shop concept

Explore the live demo ↗

Work completed. Built a responsive café page with an atmosphere-led opening, menu categories that switch in place and a demonstration pre-order form. Replaced decorative cup artwork with café photography and added a working demo basket to the menu.

Stack and tools. Built with HTML, CSS and JavaScript. The café photograph comes from Lummi. Fontjoy informed the type pairing; the implemented site uses Montserrat and Manrope.

Visual decisions. Espresso brown and warm cream are paired with a sharp lime accent for buttons and small highlights. The contrast makes practical actions easy to spot without making the menu hard to read.

Competitive thinking. A café visitor is usually checking what is available and whether ordering ahead is possible. Category tabs answer the first question quickly; the form demonstrates the second path.

Automation and data. The menu tabs change visible items without a page reload. The form validates required fields and confirms a demo pre-order; no message reaches the café and no payment is processed. Menu tabs and basket totals update in the browser. No payment, inventory or order delivery is connected.

Build time. Actual working hours were not logged.

10 / MARGIN — independent publishing concept

Explore the live demo ↗

Work completed. Built an editorial site with a book-led opening screen, a three-edition collection, topic filters, mobile menu and contact form. Added an edition detail reader alongside the existing category filters.

Stack and tools. Built with HTML, CSS and JavaScript.

Visual decisions. Deep brown, paper cream and a clay accent echo printed material. A serif headline and product photography give the books a stronger presence than a generic software-style landing page.

Competitive thinking. An independent publisher needs to show its point of view before asking for contact. The opening image establishes that direction, while filters help visitors browse by interest.

Automation and data. Topic filters update the visible books and count immediately. The mobile menu opens and closes. The enquiry form is a demo; it does not send data to a publisher. Filtering and edition notes run locally. The enquiry form is a browser-only demonstration.

Build time. Actual working hours were not logged.
